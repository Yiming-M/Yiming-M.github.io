## 1. 定位

个人学术主页 + 笔记 + 摄影。当前不找工作（最早 2028 年 1 月），首页的任务是让人记住你，而不是速览简历。

全站分两种节奏：

| 节奏 | 页面 | 原则 |
| --- | --- | --- |
| 展示 | 首页、Albums | 炫酷、沉浸式视觉：3D、全屏图像、滚动叙事 |
| 阅读 | About Me、Publications、Posts | 沉浸式阅读：安静、专注、少干扰 |

全站中英双语，两种语言的结构和功能完全一致。

**导航**：四个标签 **About Me · Publications · Posts · Albums**（中文页显示为 **关于我 · 论文 · 文章 · 相册**），另有搜索、语言切换和主题切换（Auto / Light / Dark）。

| --- | --- |

## 3. 视觉语言

### 3.1 字体

- **全站**：LXGW Bright GB（霞鹜文楷 Bright 简体规范字形版），使用 Regular、Medium、Italic 三款。
- **加载方式**：自托管，不依赖第三方 CDN。用 `cn-font-split` 把字体按字符切成带 `unicode-range` 的 woff2 小文件，浏览器只下载页面上出现的字。切分结果提交进 `public/fonts/`，附 OFL 许可证。源 TTF 不进仓库。`font-display: swap`。
  - 不整包直接放的原因：单个字重的 TTF 就有 13.6MB，首次访问要等很久，文字还会在系统字体和文楷之间跳变。
  - **分块大小约 16KB**（工具默认 70KB）。文楷字形复杂，一页里的常用字会分散在很多块里，块越小，多下载的无关字越少。
  - **只保留常用字**：丢弃只含生僻字的块，保留约 1 万字，覆盖 GB2312 全部 6763 个汉字。字体声明 CSS 因此缩到约 1/3（gzip 后 48KB），仓库里的字体文件约 6.8MB。没有保留的生僻字自动用系统字体显示，不会显示成方块。
  - **实测（2026-11-17）**：短的中文页（如栏目页）首次访问的字体下载量约 386KB，包括 37 个请求和 CSS；满足 Phase 1 定的 500KB 预算。长文（约 800 个不同汉字）只算 Regular 一款就约 1MB。字体块各页共用，浏览器会缓存，所以只有第一次访问时成本较高。
  - **实测（2026-11-18，Phase 6 的 Lighthouse）**：中文首页首次访问的字体约 507KB（58 个请求）加声明 CSS 48KB，略超 500KB 预算：首页三个项目页的标题、标注和署名合起来用到的字较多。声明 CSS 是阻塞渲染的资源，Lighthouse 估计手机上会推迟首屏约 0.6 秒。暂不处理，记录在此。
- **代码**：系统等宽字体。
- **公式**：MathJax（构建时渲染为 SVG）。

### 3.2 颜色与主题

- 保留三种主题：Auto、Light、Dark。
- 首页 3D 区域不随主题变化，背景色为 `#070a12`（与静态图背景一致）。
- **强调色（Phase 4 定稿）**：取自首页 MRI 里腺体的青绿色，让首页和内页呼应。浅色主题用 `#0f766e`（与底色的对比度约 5.0:1），深色主题用 `#5ce6d2`。病灶的橙色 `#ffa04a` 只在首页使用。
- 底色沿用暖纸色（浅色）和深墨色（深色）。
- 文章分类颜色（关系图节点）：论文笔记用强调色，读书笔记用蓝色 `#4f7be0`，随笔用琥珀色 `#c47f17`。

### 3.3 动效

- **展示页面**：3D、滚动叙事、图像转场。
- **阅读页面**：只有不超过 200ms 的颜色和透明度过渡。
- **页面切换**：用 CSS 的跨文档 View Transitions（`@view-transition { navigation: auto; }`），不写 JS；不支持的浏览器照常跳转。
- **`prefers-reduced-motion: reduce`**：所有 3D 和滚动动画换成静态图和静态布局。

### 3.4 可访问性底线

正文对比度达到 WCAG AA；所有交互键盘可达；焦点可见；每页设置正确的 `lang`；图片有 alt；灯箱支持键盘和屏幕阅读器。

## 4. 首页

**构成**：全屏 3D 前列腺 MRI，左上角站名（英文页 “Gradient of Thought”，中文页 “思索の勾配”），四个标签，语言和主题控件，角落一行数据来源署名。首页不放简介、CV、论文列表和搜索框，这些都在其他页面。

**多个项目页（2026-11-17 加入）**：首页不只展示当前的研究方向。右侧竖排的小方块（当前页实心；手机上改为横排在右上角，与项目名同一行，免得压住图片）切换项目，鼠标滚轮或触控板、键盘 ↑ ↓、手机上下滑动也能切换；当前页写进网址的 #，如 `/#crowd`。每页只显示项目名，以及与画面相关的少量数字或标注。

| 页 | 项目 | 画面 | 数据 |
| --- | --- | --- | --- |
| 1 | 前列腺癌主动监测（当前） | 三维解剖模型 + 切面（见下文） | PI-CAI，CC BY-NC 4.0 |
| 2 | 人群计数（博士期间：CLIP-EBC、ZIP、FusionCount） | “密度地形”：照片平放，由人头标注生成的密度图（MCNN 的几何自适应高斯核，总和等于人数）从照片上升起成发光的地形，人越密越高；加法混合的发光玻璃质感（与 MRI 页一致），深蓝 → 青绿 → 近白，表面画等高线。开场先正对照片 1 秒，再用约 3.6 秒把照片放倒、地形升起，左侧人数同时从 0 数到总数；鼠标移到页面最上方是正对的原照片，往下移照片逐渐放倒、地形升起，最下方照片放得最平，看到一座座山峰；左右移动旋转。鼠标停在照片或地形上时，旁边显示该处的人群密度（2026-11-18 加入）：沿视线找到鼠标碰到的地形表面，取那一点周围 100×100 原照片像素里的人数（没有相机标定，算不出每平方米的人数）；不逐点读数，因为密度图是一个个人头的小峰叠成的，逐点读数会随鼠标挪动一两个像素大起大落。静态版是照片叠加平面热力图和等高线。3D 数据约 400 KB | NWPU-Crowd 验证集第 251 张（从舞台后方拍的演唱会观众，639 个人头），取自作者服务器上 ZIP 仓库里的数据 |
| 3 | 驾驶员监控（博士期间） | “夜间座舱”：把深度图抬成点云（约 17 万个点），虚拟相机放在原相机的位置，正对时与原图重合。点云平时显示夜间彩色相机拍到的样子（很暗，几乎看不清）；鼠标处是一个圆形“镜头”，镜头中心显示红外图（夜里也清楚），外圈按深度着色（远处深蓝、近处青绿到近白，与人群页同一套配色）并画等深线（生成的深度图里五官起伏很弱，打光看不出东西，等深线在脸上是一圈圈同心线），镜头边缘一圈细光，红外区边界一圈虚线。镜头半径是图像高度的 27%。鼠标同时让点云小幅转动（左右 ±16°、上下 ±9°），看出立体。前方、侧方、上方三个机位：左侧三个按钮切换，切换时点云散开再聚成新机位的样子；没点按钮时每 7 秒自动换一个机位。开场时点从四周飞来聚成前方机位。鼠标没进页面时镜头停在脸上。静态版是前方机位的夜间彩色图，脸上叠加同样的镜头。深度图是生成的相对深度，三个机位之间没有标定，所以每个机位单独成一片点云，转动范围也只能小，转大了会露出被挡住的空洞。生成的彩色图偏亮，不像真实的夜间车内，统一调暗。3D 数据约 510 KB | ChatGPT 生成的九张图（三个机位 × 彩色、红外、深度），2026-11-18 作者提供；页面上不标注来源（作者决定：个人网站，不需要）。DAD 数据集的许可禁止发布，不能用真实数据 |

各页的 3D 场景只在第一次切到该页时加载，离开时暂停渲染。

**3D 场景（第 1 页）**：

- **数据**：PI-CAI 公开数据集的病例 10807_1000823。包括 T2 加权序列；专家勾画的病灶（ISUP 2 级，位于右后外周带）；AI 分割的外周带和移行带（Yuan23）。许可为 CC BY-NC 4.0（影像和标注均是），首页右下角署名。2026-11-17 经作者同意下载，只按字节范围取了这一个病例，约 20 MB。
- **呈现（2026-11-17 改为方案 C：解剖模型 + 切面）**：
  - 外周带（青绿 `#5ce6d2`）、移行带（淡紫 `#a5a8ff`）、病灶（橙 `#ffa04a`）是三个平滑的三维曲面。曲面从分割生成：先重采样成 0.9 mm 各向同性体素并高斯平滑，消除 3 mm 层厚的台阶，再提取等值面（Surface Nets），最后做 Taubin 平滑。曲面不受体素分辨率限制，所以画面清晰。
  - 材质是“X 光玻璃”：正对视线处几乎透明，边缘发亮，层层叠加。
  - 一张原始分辨率（约 0.34 mm）的横断面 MRI 切片水平穿过腺体，切片上画出三个区域的彩色轮廓，四周渐隐融入背景；切片下方的曲面调暗，形成前后关系。
  - 相机从斜上方约 32° 俯视。宽屏（宽高比 > 1.35）时模型偏右，左侧是三条标注（名称加一句说明），用虚线引线连到模型上，引线随模型转动实时更新；不够宽时标注变成左下角的图例。
  - 改用方案 C 的原因（作者反馈）：之前的体渲染把 19 层叠在一起看，偏朦胧；居中的圆形画面在宽屏上两侧留白太多；外周带和移行带没有分开着色。
- **开场**：模型从侧转约 30° 转正，切片从腺体顶部扫到病灶所在的层面。
- **交互**：鼠标左右移动，模型绕竖直轴旋转 ±35°；鼠标上下移动，切片在腺体里上下扫过（屏幕上方是头侧），屏幕下方显示当前层面序号。带阻尼缓动；鼠标移出画面后回到正面和病灶层面。
- **背景**：渲染出来后再定，不一定是纯黑。
- **降级**：手机（粗指针或窄屏）、开启了 `prefers-reduced-motion`、或浏览器不支持 WebGL2 时，显示病灶所在层面的原始分辨率横断面，叠加三个区域的彩色轮廓（离线生成的静态图）。
- **预算**：three.js 只在首页按需加载；体数据压缩后不超过 3MB；桌面宽带下 3 秒内可以交互。
  - 实测（2026-11-17，方案 C）：切片 344×344×15（0.34 mm，gzip 后 1.56 MB）、标签 12 KB、三个曲面 352 KB、静态图 473 KB；3D 脚本（含 three.js）压缩前约 530 KB。桌面端下载约 2.5 MB，手机只下载静态图。
  - 只在需要变化时渲染（开场动画、鼠标移动），静止时不占用 GPU；高分屏下最多按 1.5 倍像素渲染。
- **预处理**：`scripts/mri/build_scene.py`（numpy、scipy、nibabel；`.mha` 用脚本里的小解析器读取，不需要 SimpleITK）裁剪出腺体周围的切片、生成曲面和静态图。离线产物进仓库，原始数据不进仓库。
- **研究方向变化时**：替换数据和着色参数即可。由你告诉我，再重新制作。

## 6. Publications

**列表页**：按年份分组，没有筛选器，没有标签。等论文多了，再建立标签系统。每条包括：

- 标题；
- 作者（你的名字加粗，共同一作标 `*`，通讯作者标 `†`）；
- venue 简称和类型徽标（Conference / Journal / Workshop / Preprint）；
- 一句话总结；
- 链接（Paper / Code / Demo / Project）。

**详情页**：标题、作者、venue 全称、日期、方法图、一句话总结、摘要、链接，以及一个 Cite 块（BibTeX 纯文本，可一键复制）。

**机器可读**：每个详情页输出 `citation_*` meta 标签和 JSON-LD `ScholarlyArticle`。BibTeX 以纯文本形式直接写在 HTML 里，AI agent 和学术爬虫无需点击就能读到。

**可选字段的处理**：
- `venue.full` 没填时，页面显示简称，citation meta 里也不输出会议或期刊名，不推测全称。
- `abstract` 没填时，不显示摘要一节。
- `bibtex` 没填时：有 arXiv 版的（`links.arxiv`，或论文链接本身是 arXiv），用 YAML 里已有的信息自动生成一条 arXiv 引用（`@misc`）；没有的，不显示 Cite 块。
- **链接**（2026-11-18 加入 `arxiv`）：已正式发表的论文，`paper` 指向出版社页面（DOI），`arxiv` 另填 arXiv 版：出版社的版本常需付费，arXiv 免费可读。预印本只填 `paper`（就是 arXiv）。按钮顺序：论文、arXiv、代码、演示、项目主页。

**数据格式**：每篇论文一个文件夹，方法图和 YAML 放在一起。

```text
src/content/publications/zip/
  index.yaml
  overview.png
```

```yaml
title: "ZIP: Scalable Crowd Counting via Zero-Inflated Poisson Modeling"
date: 2025-07-31
type: preprint            # conference | journal | workshop | preprint
venue: { short: arXiv, full: arXiv preprint }
authors:
  - { name: Yiming Ma }
  - { name: Victor Sanchez }
  - { name: Tanaya Guha }
  # 可选标记：equal: true（共同一作）、corresponding: true（通讯作者）
links: { paper: "https://doi.org/10.1109/TIP.2026.3752245", arxiv: "https://arxiv.org/abs/2506.19955", code: "…", demo: "…" }
image: ./overview.png
tldr: { en: "…", zh: "…" }
abstract: { en: "…", zh: "…" }
bibtex: |
  @article{…}
```

## 7. Posts

### 7.1 来源与同步流程

- **唯一来源**：Obsidian 笔记库，路径记录在 `AGENTS.md` 里。
- **发布范围**：只发布 frontmatter 里写了 `publish: true` 的笔记。
- **同步由 AI agent 按操作手册完成，不写同步脚本。** 手册写在 `AGENTS.md` 的“同步笔记”一节，Claude 和 Codex 用同一份。步骤：
  1. 只读访问笔记库，找出 `publish: true` 的笔记。
  2. 把笔记原文和它引用的附件复制到 `src/content/posts/<slug>/`：中文原文存为 `zh.md`，附件和它放在同一个文件夹。原文语法不改写，转换由构建时的插件完成。
  3. 按下面的检查项逐条检查，把问题列给你。不自动修改笔记库。
  4. 如果笔记库里 Admonition 插件的配置（自定义类型的颜色、图标、标题）有变化，同步更新 `src/data/admonitions.json`。
  5. 把新增或改动的笔记译成英文，存为同一文件夹下的 `en.md`。
  6. 构建通过后，在本地预览给你检查。
- **检查项**：
  - 缺少 `slug` 或 `description`；
  - `slug` 重复；
  - `series_order` 重复，或与标题里的编号不一致；
  - 引用了不存在的标题或块；
  - 附件缺失。

  构建本身也会兜底：frontmatter 不符合 schema 时构建失败；无法解析的块引用会输出警告。
- **对笔记库只读**，除非你明确要求修改。
- **翻译**：英文版只存在于仓库，笔记库保持纯中文。
- **发布**：由你检查，由你决定是否提交和推送。**agent 不推送。**
- **草稿预览**：模板阶段，或者你想先看看效果时，agent 把未标记发布的笔记复制到 `src/content/posts-drafts/`（视频等附件放 `public/drafts/`）。这两个目录被 gitignore，只在 `npm run dev` 或 `INCLUDE_DRAFTS=1 npm run build` 时出现，正式构建和部署不会包含（开关见 `src/lib/drafts.mjs`）。DINOv3 01、02 就走这个通道。
- **附件位置**：图片和 `zh.md` 放在同一文件夹，构建时由 Astro 压缩成 WebP（实测 2MB 左右的截图压到 100–400KB）；视频等其他附件放 `public/media/posts/<slug>/`，原样提供。
- **完整步骤**写在 `AGENTS.md` 的“同步笔记”一节。

### 7.2 frontmatter

沿用你现在的字段，只新增两个：

```yaml

description: "…"
date: 2026-11-13
updated: 2026-11-13
series: "手撕 DINOv3"
series_order: 1
tags: [ai/deep-learning, ai/computer-vision]
slug: dinov3-01     # 新增：网址，只用小写字母、数字和连字符

```

- **slug** 由你写在笔记里。如果缺失，agent 会提议一个，征得你同意后才写入笔记库。
- **分类**由笔记所在的文件夹决定：`论文/` 对应 Papers（中文页显示“论文笔记”），`书籍/` 对应 Books（“读书笔记”），`随笔/` 对应 Notes（“随笔”）。中文名避开了导航里的“论文”（Publications）。
- **阅读时长**自动计算。
- **不需要封面图。**

### 7.4 阅读页（沉浸式阅读）

- **布局**：
  - ≥1200px：左栏是大纲（固定在视口内），中间是正文（中文约每行 40 字，英文约每行 70 字符），右栏是局部关系图和反向链接。
  - 1024–1199px：右栏内容移到正文末尾。
  - <1024px：大纲收进顶部的抽屉，关系图和反向链接放在文末。
- **页头**：向下滚动时自动隐藏，向上滚动时出现。页顶有一条细的阅读进度条。
- **系列**：文首显示“系列 · 第 n 篇 / 共 m 篇”，文末有上一篇和下一篇。
- **悬停预览**：桌面端鼠标在站内链接上停留 300ms，弹出目标笔记的标题和开头段落（同源抓取目标页面并缓存）。触屏设备不启用。
- **元信息**：发布日期；更新日期（与发布日期不同时才显示）；阅读时长；标签。英文页不加 AI 翻译声明。

### 7.5 关系图

- **节点**：已发布的笔记为实心节点。被链接但尚未创建或未发布的笔记为灰色空心节点，这与 Obsidian 中未创建笔记的显示方式一致；灰色节点不可点击，悬停时显示名称。
- **边**：笔记之间的双链。
- **局部图**：当前笔记加上它的一跳邻居，包括灰色节点。
- **名称显示**：文章节点始终显示名称；灰色节点（多为名字很长的待写论文笔记）只在悬停相关节点或放大到 3 倍以上时显示，避免挤成一片。
- **初始视图**：打开页面时布局一次算完，并自动缩放到占满画布；拖动节点时才播放动画。
- **全站图**：`/posts/graph/`，2D，与 Obsidian 一致。可拖拽、缩放，点击节点跳转，按分类着色。
- **实现**：构建时生成 `graph.json`；前端用 d3-force 计算布局、Canvas 绘制，只在需要的页面加载。中英文各一张图。

### 7.6 索引页 `/posts/`

分类切换 All / Papers / Books / Notes；系列聚合显示，每个系列下列出篇目；按日期倒序。

### 7.7 搜索

- 用 Pagefind，在构建后对 `dist/` 建索引。中英文按 `lang` 分别建索引。
- 搜索范围覆盖 Posts、Publications、Albums 和 About。

## 8. Albums

### 8.1 数据结构

每个相册一个文件夹，里面是照片和一个 `album.yaml`：

```text
src/content/albums/2025-scotland/
  album.yaml
  IMG_0001.jpg
  IMG_0002.jpg
```

```yaml
title: { zh: 苏格兰高地, en: Scottish Highlands }
date: 2025-08                  # 用于排序
place: { zh: 苏格兰, en: Scotland }
cover: IMG_0001.jpg
intro: { zh: "…", en: "…" }    # 可选
placeholder: true              # 可选：模板阶段的占位相册，页面上标注“占位图”（2026-11-18 加入）
photos:
  - src: IMG_0001.jpg                    # 同目录下的文件名
    caption: { zh: "…", en: "…" }
  - src: https://example.com/photo.jpg   # 或完整链接
    caption: { zh: "…", en: "…" }
    exif: { camera: Canon EOS R8, lens: "…", focal: 35mm, aperture: f/8, shutter: 1/250, iso: 100 }
    # exif 可选：链接图片读不到 EXIF 时手写；写了就覆盖自动读取的值
```

- **本地文件**：
  - 构建时读取 EXIF 并显示：相机、镜头、焦距、光圈、快门、ISO、拍摄时间。
  - 构建时生成多尺寸的 AVIF/WebP，用于网格和正文展示。
  - 灯箱里的“查看原图”提供原文件。**不限制原图分辨率。**
- **链接图片**：直接引用，不做处理。尺寸在构建时探测；探测失败时，需要在 YAML 里写明 `width` 和 `height`。
- **GPS**：不剥离，也不在页面上展示。
- **体积提醒**：构建结束时打印 `dist/` 的总大小。GitHub Pages 站点上限为 1GB，超过 800MB 时给出警告。
- **文字**：中文由你写，哪怕只写地名；英文由 AI 翻译。AI 不编造经历。

### 8.2 视觉

具体效果在 Phase 5 先出样稿，由你选。2026-11-18 定稿：索引页用“全屏封面”，相册页用“叙事排版”，即下面的方向（落选的样稿见 §11）。方向如下：

- **索引页**：全屏展示，相册封面大图随滚动逐个切换（scroll-snap），封面缓慢推近；桌面端悬停时有 WebGL 液态扭曲过渡；每个相册的强调色从封面图中提取。
  - 实现细节（2026-11-18）：这一页的页头不自动隐藏，否则页头一藏，顶部会露出上一屏的边；强调色在浏览器里从已下载的封面提取（构建时读像素需要额外的图片解码依赖）。
- **相册页**：全屏封面开场，之后照片按节奏排版（满幅、并排、留白交替），滚动时渐显；照片下方用小字显示 EXIF；点击进入灯箱（PhotoSwipe：缩放、手势、键盘操作）。
- **主题**：页面框架（导航、文字）跟随主题；照片本身不加任何滤镜。
- **降级**：开启 `prefers-reduced-motion` 时去掉推近、扭曲和渐显；手机上不做 WebGL 扭曲。
- **测试数据**：模板阶段使用生成的占位图，并明确标注为占位。你提供照片后替换。

### 9.1 可维护性

日常维护（同步笔记、添加论文和相册）都由 AI agent 完成，所以代码要让下一个 agent 能读懂、能放心改。

- **注释写足，用中文**：
  - 每个组件、插件和脚本开头，说明它负责什么、输入输出是什么、和哪些文件相关。
  - 非显而易见的逻辑，写明原因而不只是做法。
  - 每个可调参数（比如 3D 的旋转角度、断点、预算）都写清楚含义和取值依据。
- **内容 schema**（`src/content.config.ts`）逐字段注释，并附上 YAML 或 frontmatter 示例。
- **`AGENTS.md`** 包含规则和操作手册：
  - 规则：不推送；事实必须有出处；对笔记库只读，除非你明确要求；翻译规则；提交前构建必须通过。
  - 操作手册：同步笔记、添加论文、添加相册、更换首页 3D 数据。
- **`CLAUDE.md`** 只写一行 `@AGENTS.md`，引用同一份内容，避免两份文件不同步。
